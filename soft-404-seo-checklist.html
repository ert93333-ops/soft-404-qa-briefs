Checklist

Soft 404 checks before launch

This is a manual QA asset for launch owners. It is not a crawler, Search Console export, PageSpeed report, or indexing guarantee.

1. 200 pages with error copy

Check successful-status URLs whose title or body says not found, no results, unavailable, empty, removed, missing, error, or similar language.

2. 204 content gaps

Confirm no indexable content is expected when a sample returns 204 or has an empty body snippet.

3. 404/410 valid-content mismatch

Review 404 or 410 rows whose title or body still looks like a valid product, article, category, guide, or documentation page.

4. Redirect chains

Shorten redirect chains near or over 10 hops and require a final target URL in migration QA samples.

5. 5xx and 429 rows

Keep server errors and rate-limit responses out of launch samples before final signoff.

6. Thin main content

For 2xx pages, make sure body snippets include meaningful main content, not only shell copy or placeholder text.

7. Owner decision

Each risky row needs a decision: keep, redirect, 404, 410, noindex, restore content, replace, or remove from launch.

8. Template grouping

Review expired products, removed posts, no-results search, archive cleanup, and docs migrations separately.

9. Post-launch retest

Retest after routing, CDN, redirect, status-code, template-copy, or content-pruning changes ship.
